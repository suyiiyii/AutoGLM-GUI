## 目标与约束

* 文档站目录固定为 `docs`。

* 不改动现有根目录的 `README*` 文件。

* 部署到 Vercel。

* 不做版本化、不做博客发布日志、不做英文。

* 暂不接入 REST/API/pdoc 自动生成。

## 技术方案

* 使用 Docusaurus（classic preset），在仓库子目录 `docs/` 作为站点根。

* 仅启用 docs 模块与静态资源；禁用 i18n、版本化与 blog。

* 使用 `Tailwind 风格一致化` 仅作轻量样式调整（如需要）。

## 目录与信息架构（精简）

* 首页：项目概览、核心价值、快速链接（指向根 README、下载/使用入口）。

* 快速开始：运行与使用的最小路径（桌面版/源码运行各 3–5 步）。

* 用户指南：

  * 连接设备（二维码、USB/WiFi 简述与注意事项）

  * 对话与任务（聊天工作流、模式选择）

  * Workflow 管理（创建/编辑/执行）

* 常见问题（FAQ）：端口/网络、API Key、设备兼容性、故障排查。

* 部署与配置：本地开发、打包与发布、Docker 部署（各要点简版）。

## 配置要点

* `docusaurus.config.ts`

  * `url` 与 `baseUrl`：Vercel 下通常 `baseUrl: '/'`；`title`、`favicon`、`logo` 设置简洁品牌元素。

  * 仅保留 `docs`，移除/禁用 `blog`、`i18n`、`versioning`。

* `sidebars.ts`

  * 按上述信息架构配置 4–5 个一级分组，确保导航简洁。

* 资源与静态文件

  * 图片放置于 `docs/static/img/`，页面引用相对路径。

## 部署到 Vercel

* Vercel 项目指向仓库的 `docs/` 子目录；构建命令 `pnpm build`，输出目录 `build/`。

* Node 20、`pnpm` 安装；如需在 Vercel 面板设置 `Root Directory` 为 `docs`。

* 推送到主分支后自动构建与发布；PR 自动生成 Preview 供审阅。

## 迁移与引用策略

* 根 `README*` 保持不变；文档站页面以“概览/快速开始”为主，必要时在页面中链接到根 README 的详细章节。

* 避免复制重复内容，文档站以用户视角精炼表达、配图与引导为主。

## 首版交付范围

* 在 `docs/` 目录初始化并配置基础站点（禁用多余模块）。

* 编写首页、快速开始、用户指南、FAQ、部署与配置五类页面（可先放占位与核心段落）。

* 在 Vercel 完成项目连接与首版部署，生成可访问 URL。
